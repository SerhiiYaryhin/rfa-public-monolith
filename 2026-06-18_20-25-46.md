# Звіт про розширення функціоналу WebRTC + Janus (18.06.2026)

Цей документ містить опис змін, внесених для відображення списку користувачів, кімнат та статусу трансляцій на тестовій сторінці WebRTC.

---

## 🔐 1. Налаштування та секрети Janus (з `application-chat.properties`)

Для взаємодії з Janus через RabbitMQ використовуються такі ключі та черги з файлу [application-chat.properties](file:///home/coder/rfa/src/main/resources/application-chat.properties):
*   **Глобальний секрет Janus (api_secret):** `janusrocks` (задається через `janus.secret`)
*   **Адміністративний секрет Janus (admin_secret):** `janusoverlord` (задається через `janus.admin_secret`)
*   **Віртуальний хост RabbitMQ (vhost):** `/rfa-dev`
*   **Черга для команд користувача:** `janus-commands`
*   **Черга для адміністративних команд:** `janus-admin-commands`
*   **Черги для відповідей від Janus:** `from-janus` та `from-janus-admin`

## 🛠️ 2. Внесені зміни в архітектуру бекенду

Для вирішення завдання було розширено кілька ключових класів у пакеті `media.toloka.rfa.webrtc`:

1.  **RPC-клієнт Janus** ([JanusRabbitClient.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/service/JanusRabbitClient.java))
    *   Додано метод `getRoomsAndParticipants()`.
    *   Цей метод виконує запити до плагіна Janus AudioBridge в межах **одної сесії** для високої швидкодії:
        *   Крок 1: Запит `list` для отримання переліку кімнат.
        *   Крок 2: Для кожної знайденої кімнати робиться запит `listparticipants` для отримання списку користувачів, їхнього стану (чи вимкнено мікрофон, чи говорить користувач).

2.  **Сховище портів та стрімів** ([PortAllocationService.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/service/PortAllocationService.java))
    *   Додано метод `getAllActiveStreams()`, який повертає список усіх активних радіотрансляцій з бази даних (таблиця `janus_live_streams`).

3.  **Сервіс трансляцій** ([RadioLiveService.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/service/RadioLiveService.java))
    *   Додано метод `getActiveRoomsInfo()`, який об'єднує дані від Janus та бази даних:
        *   Запитує кімнати та користувачів у Janus.
        *   Звіряє ID кімнат зі списком активних трансляцій.
        *   Якщо ID кімнати збігається з кімнатою активного стріму, додається ознака `"is_streaming": true` та назва станції (`station_id`).

4.  **REST-контролер** ([JanusLiveController.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/controller/JanusLiveController.java))
    *   Додано кінцеву точку `GET /api/v1/webrtc/stream/rooms`.
    *   Повертає об'єднану інформацію про кімнати, користувачів у них та наявність активного аудіопотоку.

## 🎨 3. Оновлення інтерфейсу тестування

Файл тестової сторінки [webrtc-test.html](file:///home/coder/rfa/src/main/resources/templates/test/webrtc/webrtc-test.html) перероблено на сучасний двопанельний адаптивний інтерфейс у темних тонах:

1.  **Ліва панель** (Керування з'єднанням):
    *   Містить поле введення ID кімнати, кнопку підключення, аудіоплеєр та лог системних повідомлень.
2.  **Права панель** (Список кімнат та користувачів):
    *   Показує список активних кімнат у режимі реального часу.
    *   Якщо в кімнаті йде трансляція потоку (джерело FFmpeg надсилає RTP потік), кімната виділяється червоною рамкою та відображає пульсуючий бейдж **🔴 LIVE** із зазначенням ID радіостанції.
    *   Для кожного користувача показується його ім'я (`display`), унікальний ідентифікатор (`id`) та його поточний стан звуку (зелений бейдж `🎙️ активний`, сірий `🔇 вимкнено` або жовтий `📢 говорить`).
    *   Для швидкого тестування біля кожної кімнати є кнопка **🔌 Підключитися**, яка автоматично підставляє ID кімнати в форму та ініціює WebRTC з'єднання.
3.  **Автоматичне оновлення:**
    *   Дані про кімнати автоматично підвантажуються через інтервал у 5 секунд (або при натисканні кнопки оновлення).

## 🔍 4. Спосіб визначення наявності трансляції

Трансляція потоку вважається активною, якщо для кімнати запущено Icecast-джерело за допомогою FFmpeg. 
Бекенд визначає це за наявністю запису в базі даних `janus_live_streams`. Запис створюється у момент виклику `/api/v1/webrtc/stream/start`, де фіксується виділений UDP порт та `janus_room_id`, і видаляється при зупинці трансляції через `/api/v1/webrtc/stream/stop`.
Ми інтегрували цю перевірку в API кімнат, що дало змогу точно підсвічувати активні ефіри на клієнтській сторінці.
