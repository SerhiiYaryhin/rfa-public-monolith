Цей документ містить опис змін, внесених для відображення списку користувачів, кімнат та статусу трансляцій на тестовій сторінці WebRTC, а також розв'язання проблеми авторизації (помилка 403 Forbidden).

## 🔐 1. Налаштування та секрети Janus (з `application-chat.properties`)

Для взаємодії з Janus використовуються такі ключі та черги з файлу [application-chat.properties](file:///home/coder/rfa/src/main/resources/application-chat.properties):
*   **Глобальний секрет Janus (api_secret):** `janusrocks` (задається через `janus.secret`)
*   **Адміністративний секрет Janus (admin_secret):** `janusoverlord` (задається через `janus.admin_secret`)
*   **Віртуальний хост RabbitMQ (vhost):** `/rfa-dev`
*   **Черга для команд користувача:** `janus-commands`
*   **Черга для адміністративних команд:** `janus-admin-commands`
*   **Черги для відповідей від Janus:** `from-janus` та `from-janus-admin`

## 🛠️ 2. Внесені зміни в архітектуру бекенду

Для вирішення завдання було розширено кілька ключових класів у пакеті `media.toloka.rfa.webrtc`:

1.  **RPC-клієнт Janus** ([JanusRabbitClient.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/service/JanusRabbitClient.java))
    *   Додано метод `getRoomsAndParticipants()`. Цей метод виконує запити до плагіна Janus AudioBridge в межах **одної сесії** для високої швидкодії:
        *   Крок 1: Запит `list` для отримання переліку кімнат.
        *   Крок 2: Для кожної знайденої кімнати робиться запит `listparticipants` для отримання списку користувачів, їхнього стану (чи вимкнено мікрофон, чи говорить користувач).
    *   Додано метод `getApiSecret()` для безпечного вилучення глобального секрету з налаштувань.

2.  **Сховище портів та стрімів** ([PortAllocationService.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/service/PortAllocationService.java))
    *   Додано метод `getAllActiveStreams()`, який повертає список усіх активних радіотрансляцій з бази даних (таблиця `janus_live_streams`).

3.  **Сервіс трансляцій** ([RadioLiveService.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/service/RadioLiveService.java))
    *   Додано метод `getActiveRoomsInfo()`, який об'єднує дані від Janus та бази даних.
    *   Додано делегат `getApiSecret()` для отримання секретного ключа з клієнта.

4.  **REST-контролер** ([JanusLiveController.java](file:///home/coder/rfa/src/main/java/media/toloka/rfa/webrtc/controller/JanusLiveController.java))
    *   Додано кінцеву точку `GET /api/v1/webrtc/stream/rooms`.
    *   **Оновлено кінцеву точку `GET /api/v1/webrtc/stream/token`**: тепер вона повертає не тільки динамічний токен, а й глобальний `api_secret` (якщо він налаштований у конфігах). Це дозволяє фронтенду автоматично конфігурувати потрібний тип авторизації.

### 🔐 Гнучка авторизація на фронтенді
Щоб уникнути помилки `403 Unauthorized request`, на сторінку додано блок **"Налаштування авторизації в Janus"**, який підтримує чотири режими:
1.  **Динамічний токен:** Використовує токен, автоматично згенерований та зареєстрований бекендом у Janus.
2.  **API Secret:** Використовує статичний глобальний пароль `janusrocks` (який підвантажується з API).
3.  **Токен + API Secret:** Використовує одночасно обидва параметри (якщо сервер Janus налаштований на максимальний рівень безпеки).
4.  **Без паролів:** Для підключення до небезпечних локальних інстансів Janus.

Авторизаційні дані (`token` та `apisecret`) тепер коректно передаються у **всіх типах запитів** до Janus:
*   Під час створення загальної сесії: `new Janus(janusConfig)`
*   Під час прикріплення плагіна: `janusInstance.attach(attachConfig)`
*   Вони зберігаються всередині хендла і автоматично прикріплюються бібліотекою `janus.js` до будь-яких транзакцій та повідомлень, що надсилаються на сервер.

### 📊 Нові елементи інтерфейсу:
*   **Права панель (Список кімнат та користувачів):** показує список кімнат, які оновлюються автоматично кожні 5 секунд.
*   **LIVE статус:** Кімнати з активними ефірами виділяються червоним та позначаються бейджем **🔴 LIVE**.
*   **Учасники:** Для кожного користувача виводиться аватар, ID та поточний статус аудіо (🎙️ активний, 🔇 вимкнено, 📢 говорить).
*   **Швидке підключення:** Кнопка **🔌 Підключитися** автоматично заповнює форму обраним ID кімнати та приєднує до неї WebRTC-аудіопотік.
