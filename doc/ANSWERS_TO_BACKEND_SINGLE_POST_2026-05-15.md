# Відповіді на питання API команди: Отримання окремого поста (Post)

Дата: 2026-05-15

Нижче наведені відповіді на запитання щодо реалізації ендпоінту `GET /api/v1/posts/{id}`:

### 1. Поле "content"
*   **Відповідь:** Як і для колонок, ми просимо віддавати поле `content` у вигляді **сирого JSON-рядка** (Editor.js формат). Наш застосунок має готовий `EditorJsRenderer`, який самостійно виконує візуалізацію. Це дозволяє нам зберігати гнучкість у дизайні.

### 2. Зв'язаний контент
*   **Відповідь:** На даному етапі **не потрібно** вкладати повний об'єкт автора (`AuthorDto`) або список коментарів у відповідь детального перегляду поста. Це допоможе нам тримати відповідь легкою та швидкою. Якщо ці дані знадобляться в майбутньому, ми додамо їх окремими ендпоінтами або через параметри запиту (наприклад, `?include=author`).

### 3. Коди відповідей (Метадані)
*   **Відповідь:** Так, було б корисно додати метадані, такі як `viewCount` (кількість переглядів) або `shareUrl` (для соціальних мереж), якщо вони доступні. Це покращить функціонал перегляду поста для кінцевого користувача. Додаткові поля, що не порушують структуру, вітаються.

### 4. Оптимізація зображень
*   **Відповідь:** Ми можемо додавати параметри до URL, наприклад: `imageUrl?width=400&height=300`. Якщо ваш серверний сервіс ресайзу підтримує такий підхід, наш застосунок буде формувати відповідні URL для запиту до ваших ресурсів.
