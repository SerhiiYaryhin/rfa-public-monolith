# Вимоги до API: Авторські колонки (Author Columns)

Цей документ описує необхідні доповнення до REST API для забезпечення коректної роботи з окремими авторськими статтями (Author Columns).

## 1. Мета
Забезпечити можливість отримання повної інформації про конкретну авторську колонку за її унікальним ідентифікатором (`id`). Це необхідно для реалізації глибоких посилань (deep linking), оптимізації трафіку та кешування даних на стороні мобільного застосунку.

## 2. Нові ендпоінти

### 2.1 Отримання детальної інформації про колонку
*   **Метод:** `GET /api/v1/columns/{id}`
*   **Опис:** Повертає повний об'єкт авторської колонки.
*   **Параметри:**
    *   `id` (path): Унікальний ідентифікатор колонки (UUID або String).
*   **Response (200 OK):**
```json
{
  "id": "string",
  "title": "string",
  "imageUrl": "string",
  "createdAt": "ISO8601",
  "authorName": "string",
  "content": "string"
}
```
*   **Response (404 Not Found):** Повертається, якщо колонка з даним ідентифікатором відсутня.

### 2.2 Пагінація для списку колонок (опціонально)
*   **Метод:** `GET /api/v1/columns`
*   **Опис:** Розширення поточного методу для підтримки пагінації.
*   **Параметри:**
    *   `page` (query, optional, default=0)
    *   `size` (query, optional, default=20)
*   **Response (200 OK):**
```json
{
  "content": [ /* list of AuthorColumn objects */ ],
  "page": 0,
  "size": 20,
  "totalElements": 100
}
```

## 3. Вимоги до реалізації
*   **Content Field:** Поле `content` повинно залишатися сумісним з поточним форматом (Plain text або JSON Editor.js, залежно від архітектурних рішень для колонок).
*   **Image Optimization:** Підтримка параметрів запиту для зображень `?width={w}&height={h}` для оптимізації завантаження в мобільному застосунку.
*   **Caching:** Коректна обробка заголовків `ETag` або `Last-Modified` для ефективного кешування на стороні клієнта.
*   **Security:** Ендпоінти повинні бути доступні для неавторизованих користувачів (Public Read).
