# Технічні вимоги до API: Пагінація контенту

Цей документ визначає вимоги до пагінації ендпоінтів контенту для реалізації функціоналу "Дивитися всі" (View All) у мобільному застосунку.

## 1. Загальні вимоги
Для всіх ендпоінтів переліку контенту (Пости, Колонки, Подкасти, Треки) необхідно впровадити стандартну пагінацію.

## 2. Параметри запиту
Кожен запит на отримання списку повинен підтримувати наступні query-параметри:
*   `page`: (Integer) Номер сторінки, починаючи з 0.
*   `size`: (Integer) Кількість елементів на сторінці (рекомендоване значення за замовчуванням — 20).

**Приклад:** `GET /api/v1/posts?page=0&size=20`

## 3. Очікувана структура відповіді
Сервер має повертати метадані пагінації разом із масивом елементів:

```json
{
  "content": [
    {
      "id": "uuid",
      "title": "string",
      "imageUrl": "url_string",
      "createdAt": "ISO8601",
      "summary": "string"
    }
  ],
  "pageable": {
    "pageNumber": 0,
    "pageSize": 20
  },
  "totalPages": 10,
  "totalElements": 200,
  "last": true
}
```

## 4. Вимоги до реалізації
1. **Сортування:** Дані повинні бути відсортовані за `createdAt DESC` (найновіші елементи першими).
2. **Consistency:** Бекенд повинен гарантувати незмінність порядку елементів між сторінками при стабільному наборі даних.
3. **Performance:** Використання пагінації обов'язкове для економії ресурсів БД та трафіку мобільного клієнта.
