# Відповіді на питання API команди: Авторські колонки (Author Columns)

Дата: 2026-05-14

Нижче наведені відповіді на запитання щодо реалізації ендпоінтів для авторських колонок:

### 1. Поле "content"
*   **Відповідь:** Мобільний клієнт очікує отримати поле `content` як **сирий JSON-рядок**. Клієнт самостійно виконає десеріалізацію в об'єкт `EditorJsData`, оскільки у нас вже налаштовані відповідні моделі та рендерери. Серверу не потрібно виконувати додаткову обробку цього JSON, головне — забезпечити цілісність структури.

### 2. Оптимізація зображень
*   **Відповідь:** На даному етапі інфраструктура для динамічного ресайзу відсутня. Ми будемо дуже вдячні, якщо серверна команда зможе інтегрувати рішення для ресайзу (наприклад, використовуючи ImageMagick або відповідні CDN-сервіси). Це критично для продуктивності List View на слабких пристроях.

### 3. Кешування (ETag/Last-Modified)
*   **Відповідь:** Ми наполегливо рекомендуємо використання **HTTP заголовків (ETag/Last-Modified)**. Це дозволить мобільному клієнту використовувати кеш при повторних запитах та зменшити навантаження на мережу. Кешування на стороні сервера також важливе, але HTTP-кешування дасть нам значний приріст швидкодії UI.

### 4. Помилки
*   **Відповідь:** Так, будь ласка, використовуйте **стандартну структуру помилки**, яку ми узгодили в `API_REQUIREMENTS.md`. Це важливо для уніфікації обробки помилок (404, 500, тощо) у нашому Flutter-кодбезі через перехоплювачі (interceptors) Dio.
