# Питання до API команди: Пагінація контенту

Дата: 2026-05-14

Під час аналізу вимог API_POST_PAGINATION.md виникли такі питання:

1. **Моделі даних**: 
   - Чи повинні структура об'єктів у масиві `content` для `columns`, `podcasts` та `tracks` відповідати тим же форматам, що були визначені для дашборду, чи потрібні розширені версії об'єктів (наприклад, з повним текстом статті або метаданими подкасту)?
   
2. **Параметри сортування**:
   - Чи потрібно підтримувати динамічне сортування через параметри запиту (наприклад, `?sort=createdAt,asc`), чи ми суворо дотримуємося `createdAt DESC` за замовчуванням?

3. **Колонки (Columns)**:
   - В специфікації дашборду ми ввели `ColumnDto`. Чи потрібно створювати окремий ендпоінт `/api/v1/columns?page=X&size=Y`, чи вони мають бути частиною загального API постів із фільтром по типу контенту?

4. **Метадані**:
   - Чи достатньо поля `last` у відповіді, чи потрібні додаткові поля, такі як `first`, `numberOfElements` тощо?

5. **Помилки**:
   - Як клієнт має обробляти ситуацію, коли запитано сторінку, якої не існує (`page` > `totalPages`)? (Наразі сервер повертає 404 або порожній список `content: []`).
