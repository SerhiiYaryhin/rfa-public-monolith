# Технічні вимоги до API: Дашборд (Головний екран)

Цей документ визначає вимоги до API для агрегованого отримання контенту на головному екрані мобільного застосунку.

## 1. Загальний огляд
Для оптимізації мобільного трафіку та швидкості завантаження інтерфейсу (скорочення кількості запитів до сервера), впроваджується єдиний ендпоінт для отримання даних дашборду.

## 2. Ендпоінт
**URL:** `/api/v1/dashboard`
**Method:** `GET`
**Auth:** Публічний (або JWT, якщо контент персоналізований)

## 3. Очікувана структура відповіді (Response JSON)
Сервер має повернути JSON-об'єкт, що містить чотири основні секції. Кожна секція повертає масив елементів згідно з раніше визначеними моделями.

```json
{
  "posts": [
    {
      "id": "uuid",
      "title": "string",
      "imageUrl": "url_string",
      "createdAt": "ISO8601",
      "summary": "string"
    }
  ],
  "columns": [
    {
      "id": "uuid",
      "title": "string",
      "imageUrl": "url_string",
      "createdAt": "ISO8601",
      "authorName": "string"
    }
  ],
  "podcasts": [
    {
      "id": "uuid",
      "title": "string",
      "imageUrl": "url_string",
      "createdAt": "ISO8601",
      "audioUrl": "url_string",
      "durationSeconds": 3600
    }
  ],
  "tracks": [
    {
      "id": "uuid",
      "title": "string",
      "imageUrl": "url_string",
      "createdAt": "ISO8601",
      "audioUrl": "url_string",
      "artist": "string"
    }
  ]
}
```

## 4. Вимоги до реалізації
1.  **Ліміти:** За замовчуванням кожна секція повинна містити не більше 5 елементів (або відповідно до налаштувань, якщо передано параметр `?limit=X`).
2.  **Сортування:** Елементи повинні бути відсортовані за `createdAt` у порядку спадання (найновіші першими).
3.  **Performance:** Відповідь повинна бути підготовлена максимально швидко (рекомендується кешування відповіді дашборду на стороні сервера на 1-5 хвилин).
4.  **Content Consistency:** Усі URL для зображень (`imageUrl`) повинні бути доступними через HTTPS та оптимізованими за розміром для мобільних пристроїв.
