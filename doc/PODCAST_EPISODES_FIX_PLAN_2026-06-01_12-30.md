# Аналіз проблеми відображення епізодів подкастів
**Дата та час:** 2026-06-01 12:30

## 1. Виявлена причина
Аналіз коду показав, що епізоди подкастів не відображаються у публічному перегляді (`/podcast/view/{puuid}`) через жорстку фільтрацію за полем `publishing`.

У методі `PodcastService.GetEpisodesByChanelPage` використовується запит:
`episodeRepository.findByChanelAndPublishingTrueOrderByPubDateDesc(chanel, pageable)`

**Основні проблеми:**
1.  **Імпортовані подкасти:** При імпорті через RSS (`PutPodcastFromRSS`) для нових епізодів поле `publishing` за замовчуванням має значення `false` (або `null`), і воно ніде явно не встановлюється в `true`.
2.  **Нові епізоди:** При ручному створенні епізоди також потребують окремої дії "Опублікувати", про яку автор може не знати.
3.  **Відсутність зворотного зв'язку:** В кабінеті автора може бути не зовсім очевидно, які епізоди опубліковані, а які ні.

## 2. Запропоноване рішення

### А. Технічне виправлення (Backend)
1.  **Автоматична публікація для імпорту:** В методі `PutPodcastFromRSS` при створенні нового епізоду автоматично встановлювати `publishing = true`, оскільки вони вже є публічними в оригінальному RSS-фіді.
2.  **Міграція даних:** Необхідно разово виконати SQL-запит або створити сервісний метод для активації прапорця `publishing` для всіх наявних епізодів, які мають прив'язаний аудіофайл.

### Б. Покращення UX (Frontend)
1.  У списку епізодів для автора (`/podcast/pedit/{uuid}`) додати чіткі позначки "Опубліковано" / "Чернетка".
2.  Додати кнопку "Опублікувати всі епізоди" для швидкого керування великими подкастами.
