# Пропозиція: Розширення компонентів Editor.js для екосистеми RFA (2026-05-09)

## Концепція
Для того, щоб Editor.js став повноцінним інструментом створення контенту на Радіо Толока, він повинен не лише підтримувати текст, а й дозволяти безшовно інтегрувати внутрішні сутності системи (треки, подкасти, профілі тощо). Це перетворить статтю з простого тексту на інтерактивний мультимедійний хаб.

## Запропоновані компоненти (Block Tools)

Ви правильно визначили основні сутності. Нижче наведено деталізацію ваших пропозицій та додано кілька важливих елементів, які ви могли пропустити.

### 1. Медіа-блоки (Ваші пропозиції)
*   **Audio Track Block:** Віджет, що дозволяє вставити трек із нашої бази. Має містити міні-плеєр, назву, автора та кнопку "Додати в плейлист".
*   **Album Block:** Картка альбому з обкладинкою та переліком основних треків.
*   **Podcast Channel/Episode:**
    *   Блок каналу: картка з описом та кнопкою "Підписатися".
    *   Блок епізоду: плеєр конкретного випуску з посиланням на повний опис.
*   **Profile/Author Card:** Блок для представлення іншого автора або гостя. Містить аватар, коротку біографію та посилання на колонку.
*   **Dynamic Carousel:** Спеціальний блок, де автор може обрати кілька постів або зображень, які будуть гортатися (наприклад, "Топ-5 треків тижня").
*   **Smart Banner:** Інтеграція рекламних або інформаційних банерів із внутрішньої системи управління рекламою.

### 2. Що варто додати (Пропущено)
*   **Radio Station Live Block:** Можливість вставити в статтю "живий" плеєр конкретної радіостанції (наприклад, якщо стаття про джаз — вставити потік Radio Toloka Jazz).
*   **Quote with Voice (TTS Integration):** Блок цитати, де окрім тексту є кнопка "Прослухати", яка використовує вбудовану систему Text-to-Speech (STT/TTS секція проекту).
*   **Interactive Polls (Опитування):** Дуже важливо для залучення аудиторії. "Який трек вам сподобався більше?" тощо.
*   **Donation/Support Button:** Швидка кнопка підтримки автора або станції (враховуючи наявність `AccController` та фінансового модуля).
*   **Section Anchor (Зміст):** Автоматичний блок "Зміст" для довгих статей, який будується на основі заголовків (H1-H3).
*   **Related Content (Auto):** Блок, який за тегами автоматично підтягує 3 схожі статті або треки.

## Особливості реалізації для RFA

1.  **Search & Pick Interface:** Кожен такий блок повинен мати "Пошук по базі". Наприклад, автор починає писати назву треку, і Editor.js пропонує варіанти з нашої таблиці `Track`.
2.  **Server-Side Rendering (SSR):** У базі даних `postbody` буде зберігатися лише UUID сутності (наприклад, `{ "type": "track", "data": { "uuid": "..." } }`). А при відображенні статті на сайті, Spring Boot повинен "розгортати" ці UUID у повноцінні HTML-віджети.
3.  **Security:** Кожен блок повинен перевіряти статус сутності. Якщо трек був видалений або прихований модератором, у статті замість нього має відображатися заглушка "Контент недоступний".

## Пріоритетність впровадження

2.  **Пріоритет B (Корисність):** Профайли авторів, Каруселі зображень.
3.  **Пріоритет C (Масштабування):** Опитування, Прямий ефір радіостанцій, Баннери.
