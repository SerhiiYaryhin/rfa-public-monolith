# План модернізації інтерфейсу створення треку (Unified Track Creation)
**Дата:** 3 червня 2026 р.
**Час:** 00:05
**Статус:** Оновлено (враховано універсальну процедуру завантаження)

## 1. Аналіз та врахування існуючих механізмів

У проекті вже реалізовано **універсальний інструмент завантаження файлів** (`StoreItemController`, `/api/store/upload`), який дозволяє завантажувати будь-який тип контенту, передаючи параметр `type` (Enum `EStoreFileType`). 

Цей механізм є базовим для поточної модернізації, оскільки він повертає стандартизовану JSON-відповідь, що спрощує роботу фронтенду.

## 2. Модернізований план змін

### Крок 1: Перехід на Універсальне API (Backend & Frontend)
1.  **Frontend:** Оновити `trackupload.html`, змінити URL завантаження в Dropzone з `/creater/trackupload` на `/api/store/upload?type=STORE_TRACK`.
2.  **Обробка відповіді:** Налаштувати JS для обробки структурованого JSON (`{success: true, uuid: "...", ...}`), який повертає універсальний завантажувач.
3.  **Збереження даних:** Виправити проблему втрати введених метаданих. Тепер форма метаданих буде доступна відразу, а UUID завантаженого файлу (або обраного зі сховища) буде підставлятися асинхронно.

### Крок 2: Інтеграція вибору зі Сховища
1.  **Контролер:** `CreaterDropGetFileController` буде отримувати список існуючих аудіофайлів користувача.
2.  **UI:** Додати вкладку "Вибрати зі сховища" у формі створення треку.
3.  **Логіка:** При виборі файлу зі списку, JS записує його UUID у приховане поле форми треку, аналогічно до результату успішного завантаження.

### Крок 3: API для створення треку (Linking)
Оскільки універсальний завантажувач лише створює запис у `Store`, нам потрібен метод для створення об'єкта `Track` та його зв'язування:
1.  **Новий Endpoint:** `POST /api/creater/track/create`
    *   Приймає: `storeUuid` (обов'язково) + метадані треку (назва, автор, альбом тощо).
    *   Виконує: валідацію `Store` об'єкта, створення `Track`, збереження в БД.
2.  **Валідація:** Перевірка, чи MIME-тип обраного `Store` відповідає аудіо (`audio/*`).

## 3. Переваги оновленого підходу
*   **Уніфікація:** Використання єдиного стандарту завантаження файлів по всьому проекту.
*   **Надійність:** Дані форми не втрачаються, оскільки процес завантаження файлу та збереження метаданих розділені, але працюють у єдиному інтерфейсі.
*   **Гнучкість:** Можливість легко перетворити будь-який аудіофайл (наприклад, результат TTS) на повноцінний радіо-трек.

## 4. Висновок
Застосування універсальної процедури завантаження дозволяє зробити інтерфейс створення треку більш стабільним та відповідним загальній архітектурі медіа-сервісів проекту. Наступним кроком буде безпосередня реалізація оновленого шаблону та API для зв'язування.
