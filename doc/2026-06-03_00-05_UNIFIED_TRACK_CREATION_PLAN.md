# План модернізації інтерфейсу створення треку (Unified Track Creation)
**Дата:** 3 червня 2026 р.
**Час:** 00:20
**Статус:** Виконано Крок 1, 3 та 4 (Backend & UI)

## 1. Виконана робота

### 1.1. Backend: Уніфікація логіки створення/редагування
*   **CreaterService:** Виправлено метод `GetTrackByStoreuuid`, який тепер коректно шукає трек за UUID об'єкта сховища.
*   **CreaterTrackController:** Повністю оновлено метод `saveCreaterEditTracks`. Тепер він працює за наступним алгоритмом:
    1. Шукає трек за UUID (режим редагування).
    2. Якщо не знайдено, шукає трек, вже прив'язаний до вказаного Store UUID.
    3. Якщо все ще не знайдено, перевіряє наявність файла у Сховищі та автоматично створює новий об'єкт `Track` (режим створення).
*   Це забезпечило єдиний Endpoint для збереження будь-яких змін треку, незалежно від того, як був отриманий файл (завантаження чи вибір зі сховища).

### 1.2. Frontend: Повний цикл створення
*   **trackupload.html:** 
    *   Інтегровано універсальний завантажувач `/api/store/upload?type=STORE_TRACK`.
    *   Додано вкладку "Вибрати зі сховища" зі списком існуючих аудіофайлів.
    *   Реалізовано постійну форму метаданих, яка не втрачає дані при виборі файлу.
    *   Додано автоматичну валідацію: кнопка "Зберегти" активується лише після того, як введено обов'язкові поля та обрано/завантажено файл.

### 1.3. Безпека
*   Додано жорстку перевірку прав власності як на об'єкт `Track`, так і на об'єкт `Store`. Креатор не може створити трек на основі чужого файла зі сховища.

## 2. Результати
1. **Збереження даних:** Тепер користувач може спочатку заповнити опис та назву, а потім вибрати файл — дані більше не зникають.
2. **Гнучкість:** Створення треку з результатів TTS або раніше завантажених файлів тепер займає лічені секунди.
3. **Чистота коду:** Видалено застарілі методи завантаження, система переведена на єдиний стандарт медіа-сервісів.
