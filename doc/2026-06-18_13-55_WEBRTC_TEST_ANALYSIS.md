# Аналіз тестової сторінки WebRTC та конфігурації черг (18.06.2026 13:55)

## 1. Аналіз webrtc-test.html
При детальному вивченні файлу `src/main/resources/templates/test/webrtc/webrtc-test.html` виявлено наступні критичні моменти:

### Конфлікт плагінів (AudioBridge vs Streaming)
*   **Проблема:** Бекенд (`JanusRabbitClient.java`) налаштований на роботу з плагіном **`janus.plugin.audiobridge`** (для голосових кімнат), тоді як тестова сторінка намагається підключитися до **`janus.plugin.streaming`** (рядок 83: `plugin: "janus.plugin.streaming"`).
*   **Наслідок:** Користувач не зможе підключитися до кімнати, оскільки плагін Streaming не "знає" про кімнати, створені в AudioBridge. Вони мають різні API та логіку роботи.
*   **Рішення:** У файлі тесту необхідно замінити `janus.plugin.streaming` на `janus.plugin.audiobridge` та змінити команду `watch` на `join`.

### Невідповідність протоколів та черг
*   **Бекенд:** Працює через **RabbitMQ** (черги `janus-commands`, `janus-admin-commands`). Це "адміністративний" шлях керування.
*   **Фронтенд:** Працює через **WebSocket** (`wss://rfa.toloka.media/janus-ws`). Це шлях реального часу для передачі медіа.
*   **Висновки щодо черг:**
    *   Черга `janus-commands` (Client API) очікує повідомлення типу `message`, які потребують активної сесії (`session_id`) та хендла (`handle_id`).
    *   Черга `janus-admin-commands` (Admin API) має приймати глобальні команди, але, як показала практика, поточна конфігурація Janus відхиляє `admin_plugin_message`.

## 2. Аналіз помилки 457 (Unhandled request)
Помилка `Unhandled request 'admin_plugin_message' at this path` свідчить про те, що транспорт RabbitMQ у даній інсталяції Janus обмежений у підтримці адміністративних команд для плагінів.

**Гіпотеза:** Janus очікує повний життєвий цикл сесії навіть через RabbitMQ для виконання команд плагінів.

## 3. Рекомендований план дій
1.  **На бекенді:** Переписати логіку створення кімнати на повний цикл:
    *   Створити сесію (`janus: create`)
    *   Прикріпити плагін (`janus: attach`)
    *   Надіслати повідомлення плагіну (`janus: message`)
    *   Знищити сесію (опціонально)
2.  **На фронтенді:** Привести `webrtc-test.html` у відповідність до плагіна `audiobridge`.
3.  **Безпека:** Перевірити, чи черга `janus-commands` має достатні права для створення сесій (зазвичай так).

**Статус:** Бекенд потребує рефакторингу для підтримки сесійної моделі через RabbitMQ, оскільки "прямий" адмін-шлях заблоковано налаштуваннями Janus.
