# Технічні вимоги до API (Mobile Integration)

Цей документ визначає вимоги до REST API сервера (Spring Boot) для інтеграції з мобільним застосунком RFA (Flutter).

## 1. Загальні принципи
*   **Формат даних:** JSON.
*   **Кодування:** UTF-8.
*   **Протокол:** HTTPS (обов'язково).
*   **Часові мітки:** ISO 8601 (UTC).

## 2. Автентифікація та авторизація (JWT)
*   **Механізм:** Bearer Token у заголовку `Authorization: Bearer <token>`.
*   **Refresh Token:** Реалізація ендпоінту `/api/v1/auth/refresh` для отримання нової пари токенів.
*   **Обробка помилок (HTTP 401):** Сервер має повертати чіткий статус при закінченні терміну дії токена, щоб застосунок міг ініціювати процес оновлення.

## 3. Стандартизована відповідь (Error Handling)
Всі відповіді з помилками (4xx, 5xx) повинні мати єдиний формат для зручного парсингу у Flutter:
```json
{
  "timestamp": "ISO8601",
  "status": "int",
  "error": "string",
  "message": "string",
  "path": "string"
}
```

## 4. Ендпоінти для радіо та поточного стану (Now Playing)
*   **GET `/api/v1/radio/current`**
    *   Повертає об'єкт з поточним треком: `{ "stationId", "trackTitle", "artist", "coverUrl", "streamUrl", "startedAt" }`.
    *   Частота оновлення: сервер має гарантувати актуальність даних.

## 5. Ендпоінти контенту (Dashboard)
*   **GET `/api/v1/dashboard`**
    *   Агрегований запит для економії запитів. Повертає список постів, колонок, подкастів, треків (за замовчуванням 5 елементів).
*   **Пагінація:** Для запитів списків (наприклад, `/api/v1/posts`) використовувати параметри `page` (start=0) та `size`.

## 6. Вимоги до продуктивності та безпеки
*   **Image Resizing:** Бекенд повинен підтримувати параметри запиту для зображень (наприклад, `?width=300&height=300`) для оптимізації трафіку.
*   **Compression:** Сервер має підтримувати Gzip/Brotli стиснення для відповідей JSON.
*   **Security Headers:** Налаштування заголовків захисту (CORS, CSP) для запобігання несанкціонованому доступу.

## 7. Обране (Favorites)
Для синхронізації стану "обране" між пристроями та сервером:
*   **POST `/api/v1/favorites/add`**
    *   Payload: `{ "id": "string", "type": "string" }` (тип: 'post', 'podcast', 'track')
    *   Response: 200 OK.
    *   **Вимога:** Ендпоінт повинен бути ідемпотентним (повторний запит для вже доданого елемента не викликає помилки).
*   **POST `/api/v1/favorites/remove`**
    *   Payload: `{ "id": "string", "type": "string" }`
    *   Response: 200 OK.
    *   **Вимога:** Ендпоінт повинен бути ідемпотентним (запит на видалення відсутнього елемента не викликає помилки).
*   **GET `/api/v1/favorites`**
    *   Параметр: `?full=true` (опціонально).
    *   Response: `List<String>` (за замовчуванням список ID). Якщо `full=true`, повертає `List<Object>` з повними даними обраних елементів.

## 9. Радіостанції
*   **GET `/api/v1/stations`**
    *   Повертає список доступних радіостанцій.
    *   Response: `List<{ "id", "name", "streamUrl", "logoUrl", "description", "metadataSource": "rfa" | "external" }>`.
*   **GET `/api/v1/radio/current`**
    *   (Повертає метадані треку для RFA станції).
*   **Вимога до розширюваності:**
    *   Сервіс метаданих має бути абстрактним. Для сторонніх станцій з `metadataSource: "external"` застосунок повинен підтримувати парсинг Icy-Metadata або звернення до зовнішніх API, визначених у параметрах станції.

## 8. Пошук та контент
*   **GET `/api/v1/search?q={query}`**
    *   Повертає список постів за запитом.
*   **Вимога до контенту (Editor.js):**
    *   Поле `content` (в об'єктах Post) повинно передаватися як рядок, що містить JSON-структуру `Editor.js`.
    *   Бекенд повинен гарантувати цілісність JSON-блоків (paragraphs, headers, images, etc.).
