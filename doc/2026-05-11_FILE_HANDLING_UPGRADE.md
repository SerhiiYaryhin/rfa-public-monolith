# Звіт про оновлення системи обробки медіа-файлів та Open Graph (11.05.2026)

## 1. Мета змін
Головною метою було вирішення проблеми відображення ілюстрацій у соціальних мережах (зокрема Facebook), які не приймають імена файлів кирилицею, а також покращення представлення контенту через розширені метадані Open Graph. Додатково проведено уніфікацію процесу завантаження файлів.

## 2. Реалізовані компоненти

### 2.1. Валідація та транслітерація імен файлів
Створено утиліту `media.toloka.rfa.radio.store.util.FilenameUtil`, яка:
*   Автоматично транслітерує українські та російські символи в латиницю.
*   Видаляє всі символи, крім латинських літер, цифр, крапок, підкреслень та тире.
*   Замінює пробіли та спецсимволи на підкреслення, запобігаючи дублюванню підкреслень.
*   **Результат:** Всі завантажені файли тепер мають безпечні імена, які коректно зчитуються будь-якими зовнішніми сервісами.

### 2.2. Зберігання розмірів зображень
Оновлено архітектуру таблиці сховища (`Store`):
*   Додано поля `width` та `height`.
*   У `StoreFileImplementation` інтегровано автоматичне визначення розмірів за допомогою `javax.imageio.ImageIO` під час завантаження.
*   Дані про розміри тепер доступні для будь-якого зображення в системі без необхідності повторного зчитування файлу з диска.

### 2.3. Розширення метаданих Open Graph
Оновлено файл фрагментів `src/main/resources/templates/fragments/common.html`:
*   Модифіковано фрагменти: `og`, `metadata`, `ogpost`, `ogtrack`, `ogprofile`, `ogpodcast`, `ogalbum`.
*   Впроваджено теги `og:image:width` та `og:image:height`.
*   Покращено логіку Twitter Cards для коректного відображення великих зображень (`summary_large_image`).
*   **Ефект:** Пости та статті тепер мають "правильний" вигляд у Facebook Debugger, а зображення підвантажуються миттєво завдяки вказаним розмірам.

### 2.4. Універсальний контролер завантаження
Впроваджено `media.toloka.rfa.radio.store.StoreItemController` (ендпоінт `/api/store/upload`):
*   Централізована точка входу для всіх типів файлів.
*   Приймає параметр `type` (`EStoreFileType`), що дозволяє використовувати один контролер для треків, обкладинок, документів тощо.
*   Забезпечує стандартизовану JSON-відповідь для фронтенду.

## 3. Міграція модулів (Подкасти)
Модуль подкастів був першим повністю переведений на нову схему:
*   **Епізоди:** Аудіофайли завантажуються через універсальний контролер, після чого прив'язуються до подкасту через новий REST-метод у `PodcastRESTController`.
*   **Обкладинки:** Обкладинки каналів та епізодів тепер завантажуються латиницею, а їх розміри автоматично потрапляють у метатеги при перегляді сторінки подкасту.
*   **Фронтенд:** Оновлено JS-скрипти в шаблонах `podcastepisodeupload.html`, `podcastcoverupload.html` та `podcastcoverepisodeupload.html` для роботи з JSON-відповідями та асинхронної прив'язки файлів.

## 4. Подальші кроки
*   Міграція модуля **Постів** (новин) на універсальний завантажувач.
*   Міграція модуля **Музичних треків** та альбомів.
*   Оновлення редактора профілю користувача.
