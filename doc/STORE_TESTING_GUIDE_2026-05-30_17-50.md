# Інструкція для тестування медіа-сховища (Store Subsystem)
**Дата створення:** 2026-05-30 17:50
**Об'єкт тестування:** Модернізований функціонал безпеки та стрімінгу StoreSiteController

Дана інструкція допоможе перевірити коректність роботи системи авторизації доступу до медіа-файлів та стабільність стрімінгу через браузер.

---

## 1. Роль: Автор (Власник файлів)

### Тест 1.1: Доступ до власних документів
1. Авторизуйтесь як Автор.
2. Перейдіть до "Сховища" (`/creater/storage/0`).
3. Виберіть будь-який завантажений вами документ (PDF, Doc) або аудіофайл.
4. Скопіюйте посилання на файл (наприклад, `/store/document/{UUID}`).
5. Відкрийте це посилання в новій вкладці того ж браузера.
6. **Очікуваний результат:** Файл успішно завантажується або відкривається для перегляду.

### Тест 1.2: Стрімінг аудіо
1. Відкрийте сторінку редагування вашого треку або посту, де є аудіо.
2. Запустіть плеєр.
3. Спробуйте перемотати аудіо в середину або кінець.
4. **Очікуваний результат:** Аудіо відтворюється плавно, перемотування працює (це підтверджує коректну підтримку заголовків `Accept-Ranges`).

---

## 2. Роль: Інший авторизований користувач (Спроба несанкціонованого доступу)

### Тест 2.1: Перевірка захисту (IDOR)
1. Отримайте UUID приватного документа або аудіофайлу, який належить **іншому** автору.
2. Перебуваючи під своїм акаунтом, введіть у браузері пряме посилання: `/store/document/{ЧУЖИЙ_UUID}`.
3. **Очікуваний результат:** Браузер повинен показати помилку **403 Forbidden**. Доступ має бути заблоковано.
4. Перевірте логи сервера (stdout). Там має бути запис: `WARN ... Спроба несанкціонованого доступу до файлу ... користувачем {ваш_email}`.

---

## 3. Роль: Адміністратор / Редактор / Модератор

### Тест 3.1: Перегляд будь-якого контенту
1. Авторизуйтесь під `ROLE_ADMIN`.
2. Використайте пряме посилання на документ будь-якого користувача: `/store/document/{UUID}`.
3. **Очікуваний результат:** Адміністратор отримує доступ до файлу без обмежень.

---

## 4. Роль: Гість (Незареєстрований користувач)

### Тест 4.1: Доступ до публічного контенту (Обкладинки)
1. Вийдіть з акаунта.
2. Перейдіть на головну сторінку або сторінку новин (`/guest/postall`).
3. Скопіюйте посилання на картинку-обкладинку поста (наприклад, `/store/content/{UUID}`).
4. Відкрийте посилання в новій вкладці.
5. **Очікуваний результат:** Картинка відображається. Публічні типи (`STORE_POSTCOVER`, `STORE_PHOTO` тощо) доступні всім.

### Тест 4.2: Доступ до приватних документів
1. Спробуйте відкрити посилання на документ: `/store/document/{UUID}`.
2. **Очікуваний результат:** Отримано статус **403 Forbidden** (або перенаправлення на логін, залежно від конфігурації Security, але не прямий доступ до файлу).

---

## 5. Перевірка продуктивності (Streaming)

### Тест 5.1: Завантаження великих файлів
1. Завантажте великий файл (наприклад, аудіо 50+ МБ або велике фото).
2. Відкрийте його через відповідний endpoint.
3. Слідкуйте за використанням оперативної пам'яті сервера (якщо можливо).
4. **Очікуваний результат:** Сервер не повинен демонструвати різких стрибків споживання RAM, оскільки дані передаються порціями (Streaming), а не зчитуються повністю в пам'ять.
