# Завдання для серверної команди: API для подкастів та епізодів

**Назва завдання:** Реалізація API для роботи з подкастами та вкладеними епізодами

## 1. Мета
Реалізувати структуру даних та ендпоінти для отримання подкастів, їх епізодів та інформації про аудіофайли епізодів.

## 2. Моделі даних

### 2.1 Об'єкт Podcast
```json
{
  "id": "string",
  "title": "string",
  "description": "string",
  "imageUrl": "string",        // Головна ілюстрація подкасту (fallback)
  "episodes": ["Episode"]      // Список епізодів
}
```

### 2.2 Об'єкт Episode
```json
{
  "id": "string",
  "title": "string",
  "description": "string",
  "imageUrl": "string",        // Опціонально. Якщо null, використовувати imageUrl з Podcast
  "audioUrl": "string",        // URL до аудіотреку епізоду
  "durationSeconds": "integer",
  "createdAt": "ISO8601"
}
```

## 3. Необхідні ендпоінти

### 3.1 Отримання списку подкастів
*   **Метод:** `GET /api/v1/podcasts`
*   **Опис:** Повертає список подкастів (базова інформація, без детальних епізодів).
*   **Параметри:** `page`, `size`.

### 3.2 Отримання детальної інформації про подкаст (з епізодами)
*   **Метод:** `GET /api/v1/podcasts/{id}`
*   **Опис:** Повертає об'єкт подкасту разом із повним списком епізодів.
*   **Параметри:** `id` (path).

## 4. Технічні вимоги
*   **Логіка ілюстрацій:** На стороні клієнта ми реалізуємо "fallback": якщо у епізоду немає власного `imageUrl`, ми автоматично використовуємо `imageUrl` самого подкасту. Просимо бекенд гарантувати, що в об'єкті подкасту це поле завжди заповнене.
*   **Формат даних:** Поля `title` та `audioUrl` в об'єкті епізоду є обов'язковими.
*   **Публічність:** Ендпоінти повинні бути публічними (`permitAll`).

## 5. Пріоритет: Середній
**Причина:** Потрібно для створення окремого розділу "Подкасти" та інтеграції плеєра епізодів.
