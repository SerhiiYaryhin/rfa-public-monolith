# План модернізації інтерфейсу створення треку (Unified Track Creation)
**Дата:** 2 червня 2026 р.
**Час:** 23:59
**Статус:** Аналіз шаблону та план змін

## 1. Результати аналізу поточного стану

### 1.1. Шаблон `trackupload.html`
*   **Логіка роботи:** Реалізовано двоетапний процес (Крок 1: Завантаження через Dropzone, Крок 2: Заповнення метаданих).
*   **Проблема з даними:** Форма метаданих (`track-details-form`) відображається лише **після** успішного завантаження файлу. Якщо користувач заповнить поля (через JS-маніпуляції) і перезавантажить сторінку, дані втрачаються. Поточна реалізація не передбачає збереження чернетки до моменту фінального натискання "Зберегти".
*   **Відсутність вибору:** Зараз неможливо вибрати існуючий файл зі сховища.

### 1.2. Контролер `CreaterDropGetFileController`
*   Метод `CreaterDropGetUploadTrack` створює порожній об'єкт `Track` при кожному запиті, що не дозволяє підтримувати стан форми.

## 2. План змін

### Крок 1: Backend (Отримання аудіофайлів)
1.  Оновити `CreaterDropGetFileController.java`:
    *   Додати виклик `storeService` для отримання списку файлів користувача з типом `STORE_FILE` або `STORE_TTS`, які мають аудіо-розширення/mime-тип.
    *   Передати цей список (`audioFiles`) у модель Thymeleaf.

### Крок 2: Frontend (Вибір зі сховища)
1.  Оновити `trackupload.html`:
    *   Додати новий блок (наприклад, "Вибрати існуючий файл") поруч із Dropzone.
    *   Реалізувати компактний список або випадаюче меню з пошуком для вибору існуючого файлу.
    *   При виборі файлу:
        *   Через JS автоматично заповнювати приховане поле `track-uuid`.
        *   Переходити до Кроку 2 (заповнення метаданих) без фізичного завантаження.

### Крок 3: Виправлення збереження даних (Persistence)
Для того, щоб дані не втрачалися і форма працювала коректно:
1.  **Зміна послідовності:** Користувач повинен мати змогу спочатку заповнити метадані (якщо хоче), а потім вибрати файл.
2.  **Реалізація через AJAX (Опціонально):** Зберігати "чернетку" треку в БД одразу після введення назви або завантаження файлу.
3.  **Фікс поточної форми:** Оновити JS-логіку так, щоб форма `track-details-form` була видимою, але кнопка "Зберегти" була заблокована до моменту, поки `track-uuid` не стане валідним (через завантаження АБО вибір зі сховища).

### Крок 4: Створення треку з існуючого файлу (API)
1.  Створити новий Endpoint `POST /api/creater/track/link-store-item`:
    *   Приймає `storeUuid` та об'єкт `Track`.
    *   Створює новий запис `Track` у БД, прив'язуючи його до існуючого `Store`.

## 3. Технічні деталі реалізації UI
*   Додати вкладки (Tabs): "Завантажити новий" та "Вибрати зі сховища".
*   Використовувати `DataTable` або простий фільтр для швидкого пошуку аудіофайлів у великому сховищі.
*   Відображати тривалість та розмір файлу для зручності вибору.

## 4. Висновок
Реалізація цього плану перетворить сторінку завантаження на потужний інструмент керування контентом. Користувач отримає гнучкість: завантажувати, вибирати зі сховища або перетворювати TTS-результати на треки в одному вікні.
