# Аналіз можливості створення треків з існуючих файлів у сховищі
**Дата:** 2 червня 2026 р.
**Час:** 23:55
**Статус:** Аналіз та технічна пропозиція

## 1. Поточний стан

На даний момент у системі створення треку нерозривно пов'язане із завантаженням нового файлу (`CreaterDropPostFileController.uploadTrack`). 

**Процес створення треку зараз:**
1. Користувач завантажує файл через Dropzone.
2. Файл зберігається в `Store` з типом `STORE_TRACK`.
3. Автоматично створюється об'єкт `Track`, який посилається на цей `Store`.
4. Користувач перенаправляється на сторінку редагування метаданих треку.

**Проблема:** Якщо аудіофайл вже завантажений у сховище (наприклад, через загальний завантажувач або як результат TTS), користувач не може перетворити його на "Трек" без повторного завантаження.

## 2. Технічна можливість реалізації

Аналіз коду показав, що реалізація функціоналу "Створити трек з існуючого файлу" є цілком можливою і потребує мінімальних змін у сервісах.

### 2.1. Backend зміни
Необхідно додати новий метод у `CreaterService` (або розширити існуючий), який буде створювати об'єкт `Track` на основі вже існуючого `Store` UUID.

**Ключові кроки:**
1. Отримати об'єкт `Store` за UUID.
2. Перевірити права власності (чи належить файл поточному користувачу).
3. Перевірити тип файлу (бажано, щоб це було аудіо).
4. Оновити тип `Store` на `STORE_TRACK` (опціонально, для консистентності).
5. Використати логіку `SaveTrackUploadInfo`, але без завантаження фізичного файлу.

### 2.2. Frontend зміни
Необхідно додати інтерфейс вибору файлу зі сховища:
* **Варіант А:** Додати кнопку "Перетворити на трек" безпосередньо у списку файлів сховища (`/creater/storage`). Це найшвидший шлях.
* **Варіант Б:** На сторінці завантаження треків додати кнопку "Вибрати зі сховища", яка відкриває модальне вікно або переходить на сторінку вибору файлів.

## 3. План реалізації

### Крок 1: Оновлення API та Сервісів
* Додати в `CreaterDropPostFileController` новий метод `POST /api/creater/track/create-from-store/{storeUuid}`.
* В `CreaterService` додати метод для валідації та зв'язування існуючого `Store` з новим `Track`.

### Крок 2: Оновлення інтерфейсу сховища
* У шаблоні `mainstore.html` (або фрагменті таблиці) для файлів з MIME-типом `audio/*` додати дію "Створити трек".

### Крок 3: Валідація та безпека
* Додати перевірку: один `Store` об'єкт не повинен бути прив'язаний до декількох треків одночасно (щоб уникнути плутанини при видаленні).
* Перевірити, чи не порушить зміна типу `EStoreFileType` роботу інших модулів (наприклад, якщо файл був завантажений як `STORE_FILE`).

## 4. Висновок

Реалізація цього функціоналу значно покращить UX, оскільки дозволить:
1. Економити трафік та час користувача.
2. Використовувати згенерований через TTS контент як повноцінні радіо-треки.
3. Уникати дублювання файлів на диску.

**Рекомендація:** Почати з реалізації Кроку 1 (Backend API) та додати кнопку дії в загальний список файлів сховища.
