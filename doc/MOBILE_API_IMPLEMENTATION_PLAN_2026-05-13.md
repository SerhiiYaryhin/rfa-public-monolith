# План реалізації API для мобільного застосунку (RFA Mobile Integration)
Дата: 2026-05-13

## 1. Підготовчий етап (Security & Auth)
- **JWT Автентифікація**: Налаштувати `SecurityConfig` на підтримку JWT замість сесій для мобільних клієнтів.
- **Ендпоінт `/api/v1/auth/refresh`**: Реалізувати контролер для оновлення токенів.
- **Стандартизація помилок**: Створити `GlobalExceptionHandler`, який повертає помилки у форматі JSON згідно з вимогами (timestamp, status, error, message, path).

## 2. Реалізація базових ендпоінтів контенту
- **Dashboard (`/api/v1/dashboard`)**: Розробити агрегуючий сервіс, який збирає дані з різних репозиторіїв (Posts, Podcasts, Tracks) та формує відповідь у форматі JSON.
- **Пошук (`/api/v1/search`)**: Реалізувати контролер з підтримкою параметрів пагінації.
- **Обране (`/api/v1/favorites`)**: Створити 3 ендпоінти (add, remove, get) у новому `FavoritesController`, додавши ідемпотентність (перевірку на наявність у БД перед зміною).

## 3. Специфічний контент (Радіо та Медіа)
- **Радіостанції (`/api/v1/stations`)**: Створити контролер для виводу списку станцій.
- **Поточний стан (`/api/v1/radio/current`)**: Забезпечити джерело даних для поточного треку, можливо, інтегрувавши з наявним сервісом метаданих.

## 4. Оптимізація та безпека
- **Зображення**: Реалізувати сервіс для динамічного ресайзу зображень через параметри запиту (наприклад, використовуючи `Thumbnails` бібліотеку або аналогічну).
- **Стиснення**: Переконатися, що у Spring Boot налаштовано `server.compression.enabled=true`.
- **Заголовки**: Налаштувати CORS та Security Headers для забезпечення безпечного доступу мобільного застосунку.

## 5. Тестування та документація
- Написати Postman-колекцію або Swagger/OpenAPI специфікацію для перевірки всіх REST-ендпоінтів.
- Перевірити коректність формату контенту `Editor.js`.

---
*Примітка: реалізацію доцільно проводити ітеративно, починаючи з Auth та Dashboard.*
