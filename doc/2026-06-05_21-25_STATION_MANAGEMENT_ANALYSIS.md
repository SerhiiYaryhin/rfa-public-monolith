# Аналіз та рекомендації щодо модернізації модуля керування радіостанціями
**Дата:** 5 червня 2026 р.
**Час:** 21:25
**Статус:** Технічний звіт та план рефакторингу

## 1. Аналіз поточної реалізації

Модуль керування радіостанціями є одним із базових компонентів системи. Він забезпечує повний цикл життя станції: від перевірки прав користувача до розгортання інфраструктури (Libretime, Icecast, Nginx) через систему черг.

### 1.1. Порядок створення та схвалення (Workflow)
На даний момент процес є лінійним та досить жорстким:
1.  **Реєстрація**: Звичайна реєстрація користувача (`ROLE_USER`).
2.  **Профіль**: Користувач повинен зайти в профайл та:
    *   Надати згоду з правилами (`confirminfo = true`).
    *   Додати поштову адресу.
3.  **Схвалення (Approval)**: Адміністратор має схвалити адресу користувача. **Це є "пляшковим горлом"**, оскільки користувач не отримує сповіщень про очікування або статус перевірки, бачачи лише повідомлення "Неможливо створити станцію".
4.  **Контракт**: Перевірка наявності безкоштовного або платного контракту.
5.  **Створення**: Автоматичне створення об'єкта `Station` та відправка ланцюжка завдань (`JOB_STATION_CREATE`, `ALLOCATE`, `PREPARE_NGINX` тощо) у RabbitMQ.

### 1.2. Стан коду (Technical Debt)
*   **Стиль написання**: Велика кількість закоментованого коду, TODO-міток та змішана мова в назвах змінних (`dbname`, `stationstate`, `toradiouser` поруч із `clientdetail`).
*   **Тонкі сервіси та товсті контролери**: Значна частина бізнес-логіки (валідація, формування завдань для RabbitMQ) знаходиться в `ClientHomeStationController`.
*   **Ручна серіалізація**: Використання `Gson` вручну перед відправкою в чергу замість конфігурації `MessageConverter` у Spring AMQP.
*   **Внутрішні класи**: Використання `private class ToRadioUser` всередині контролера для обробки форм замість повноцінних DTO.

## 2. Рекомендації щодо рефакторингу коду

### 2.1. Архітектурні зміни
1.  **DTO (Data Transfer Objects)**: Створити окремий пакет `media.toloka.rfa.radio.station.dto` для обміну даними між UI та сервісами (`StationCreateDTO`, `StationControlDTO`, `StationPasswordDTO`).
2.  **Винесення логіки в Service**: 
    *   Перенести методи перевірки можливості створення (`CreateCheckConfirminfo`, `CreateCheckAddress` тощо) з `StationService` у спеціалізований валідатор або залишити в сервісі, але очистити від залежностей `Model`.
    *   Логіку формування `RPCJob` винести в `StationService.triggerStationCreation(station)`.
3.  **Уніфікація RabbitMQ**: Налаштувати `Jackson2JsonMessageConverter`, щоб передавати об'єкти безпосередньо через `template.convertAndSend(obj)`.

### 2.2. Чистота коду (Clean Code)
1.  **Видалення "сміття"**: Видалити всі закоментовані блоки коду та старі методи, що не використовуються.
2.  **Стандартизація іменування**: Привести всі поля до `camelCase` (наприклад, `dbname` -> `dbName`, `stationstate` -> `isRunning`).
3.  **Логування**: Замінити системні виводи `System.err.println` на `logger.error`.

## 3. Рекомендації щодо покращення інтерфейсу (UI/UX)

### 3.1. Керування станцією (Dashboard)
Поточний інтерфейс розбитий на багато окремих сторінок (`stations`, `controlstation`, `settoradiouser`).
*   **Рекомендація**: Створити єдиний "Центр керування станцією" на базі вкладок (Tabs) або карток, де на одному екрані будуть:
    *   Статус (Online/Offline) з кнопками Start/Stop.
    *   Налаштування мовлення (Icecast).
    *   Керування паролями.
    *   Посилання на Libretime панель.

### 3.2. Покращення процесу створення (Wizard)
Замість того, щоб показувати помилку "Неможливо створити", впровадити інтерактивний помічник:
*   **Крок 1**: Згода з правилами (якщо не надана).
*   **Крок 2**: Заповнення адреси.
*   **Крок 3**: Статус схвалення адміном (відображення прогресу: "Ваша адреса на перевірці").
*   **Крок 4**: Вибір контракту та запуск.

### 3.3. Візуальні елементи
1.  **Індикація стану**: Використовувати анімовані "пульсуючі" індикатори для процесу запуску/зупинки станції (зараз користувач не знає, чи працює RPC завдання).
2.  **Модальні вікна**: Зміна пароля та назви станції має відбуватися у модальних вікнах (Bootstrap Modals) без перезавантаження всієї сторінки.
3.  **Копіювання в кліпборд**: Додати кнопки "Скопіювати URL" та "Скопіювати пароль трансляції".
